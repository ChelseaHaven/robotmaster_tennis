# 发球任务

实现位于 `launcher_task.c`，参数集中在 `launcher_task.h`。参考新版 F407 的四工位判球、搜索与拨球流程；直接通过本工程 PWM 设置角度，不使用参考工程的串口舵机板、脉宽标定命令或 CAN 上层协议。

## 工位与压力参数

- 四个工位分别配置为 `LAUNCHER_BALL_SLOT0_ANGLE_DEG` ～ `SLOT3_ANGLE_DEG`，默认 0/90/180/270°，可以分别按实物标定；工位编号保持 0～3。
- 上电从 PWM 初始化的 135°指令角，在 1200 ms 内插值到起始工位（默认工位 0），再等待 1000 ms。没有实际角度传感器，动作完成只代表指令与等待时间完成。
- 左传感器默认对应压力数组索引 1（地址 0x02），右传感器对应索引 0（地址 0x01），沿用参考工程安装关系，可通过宏调整。
- 左侧有球往工位编号减小方向拨，右侧有球往编号增大方向拨。两侧有球时在中间两个工位间往复。
- 有球阈值默认 30，无球阈值 20；中间区间保持已确认状态。连续两次新的有效压力应答才确认；重复读取同一快照不算新采样。
- `pressure_data_t.sample_count` 只记录新应答计数，在线状态仍复用 `detect_task`。

## 一次性拨球

1. 下行 `0x0103` 为单字节 0/1，0→1 产生一次事件；上电或命令断流 500 ms 后，必须先收到 0 再收到 1。
2. `launcher_task` 调用 `host_comm_get_launcher_feed()` 取出事件；定位、工位移动、稳定等待或已有拨球请求时，新的事件直接丢弃。
3. 接受请求时清除旧压力资格，重新等待新采样；两侧压力在线、稳定，发球目标通信有效且两台 OID 电机反馈在线、无故障时，才启动新的工位移动。这里不要求转速已达到目标。
4. 有合法球路时移动一个工位，默认 500 ms，再稳定等待 1000 ms，只计作一次拨球。
5. 没球时在四工位间搜索，到端点反向。端点处占球但无法向外拨时，另一侧确认无球才向内回移一步，回移不计作拨球。
6. 等待前置条件最多 8 s；实际搜索条件具备后另计 8 s。只有确认四个工位都空才归类为无球，否则为搜索超时、压力离线或限位阻塞。超时停止锁存，新请求才重新开始。
7. 一次拨球完成后默认自动准备下一颗，但不会自动再拨球；设置 `LAUNCHER_BALL_AUTO_PREPARE=0` 可取消自动准备。

## 其他控制与断流

- 下行 `0x0102` 的两轮 RPM 和 pitch 目标持续独立更新，不触发或打断分球动作。
- 发球目标超过 500 ms 未更新时两轮发零电流，pitch 保持最后指令角；未开始的拨球和备球搜索取消。
- 已开始的分球工位移动及稳定等待走完。拨球中发生断流后，即使随后重连，完成本次动作也不会自动准备下一颗；需要新的拨球边沿。
- 所有等待均通过状态和时间推进，不在分球动作中阻塞串口、CAN、压力轮询或 pitch 更新。
- 参考工程的在线标定、人工按钮和复杂会话协议未移植，后续直接调整本工程的角度及时间宏。

主机行为验证：`python3 tests/test_launcher_ball.py`。该测试使用真实状态机代码检查新采样判球、单次动作、忙时丢弃、端点回移、搜索超时和掉线处理；不替代机械角度与压力阈值的实机标定。
