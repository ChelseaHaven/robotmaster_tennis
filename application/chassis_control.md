# 遥控器与 3566 底盘控制

## SWD 三档

按这台 HT-10A 实测的 SBUS 原始值：

| SWD 位置 | CH8 | 模式 |
| --- | --- | --- |
| 朝操作员、最里面 | 1792 | 急停，清除轮速 PID 并发送四路零电流 |
| 中间 | 992 | 遥控器控制 |
| 朝外、最外面 | 192 | 接受 3566 速度命令 |

档位允许 ±120 的误差；未知档位、遥控器未连接、丢帧、失控或超过 100 ms 未更新均进入急停。上位机模式也要求遥控器在线，以便 SWD 能随时切换到急停。

此处急停是软件停止驱动，不是硬件断电或主动抱死制动；原有零电流处理会允许车轮惯性滑行。

## 遥控器模式

原始通道中值 992，最小值 192，最大值 1792。中心死区为 ±30，死区外线性映射到速度：

- CH4：左摇杆左推 → 车体左移，右推 → 右移。
- CH3：左摇杆前推 → 前进，后拉 → 后退。
- CH1：右摇杆左推 → 逆时针转，右推 → 顺时针转。
- CH2：右摇杆前后，不参与控制。

默认平移合速度上限 0.5 m/s，角速度上限 1 rad/s。左摇杆斜推时按比例限幅，不会变成 0.707 m/s。

映射、方向、死区及速度上限集中在 `application/chassis_behaviour.h`。`chassis_behaviour.c` 负责模式与速度选择，由现有 `chassis_task` 调用，没有新增线程。

## 3566 速度命令

单片机端改为：

| 项目 | 定义 |
| --- | --- |
| 命令号 | `0x0101`，`HOST_CMD_CHASSIS_VELOCITY` |
| 负载 | 三个小端 IEEE 754 float32，共 12 字节 |
| 顺序 | `vx`、`vy`、`wz` |
| 单位 | m/s、m/s、rad/s |
| 坐标系 | 车体系 X 向前、Y 向左，绕 Z 逆时针为正 |

3566 之后按上述定义发送即可，例如 Python 的负载编码：

```python
payload = struct.pack('<3f', vx, vy, wz)
```

仍使用原协议帧头、长度、序号、CRC8 和 CRC16。命令 `0x0101` 已直接替换为速度定义，不再解析位姿。

- 切入 3566 档后，等待切档后收到的新速度帧，避免使用急停或遥控期间缓存的旧指令。
- 速度命令超过 500 ms 未更新，输出零电流；有效命令恢复后继续。
- 平移合速度限制为 0.5 m/s，角速度限制为 ±1 rad/s，与遥控模式一致，可在 `chassis_behaviour.h` 修改。
- `host_comm_get_velocity()` 提供线程安全的最新速度快照，`valid` 表示未超时。
- 四轮速度上发保持 `0x0101`，4 个小端 float32，m/s，约每 10 ms 一帧。
- 本次没有修改 3566 程序。旧位置包与新速度包的命令号和长度相同，单片机无法区分；3566 改为发送速度之前，保持急停或遥控档。

## 底盘与状态

所有模式统一经过 `chassis_behaviour_update()` 选择速度，再进行麦轮解算和轮速 PID；原有外部直接设置速度的 `chassis_set_velocity()` 接口已移除，避免绕过 SWD 仲裁。

```c
#include "chassis_task.h"
chassis_control_t control;
chassis_get_control(&control);
// control.mode：急停、遥控或上位机
// control.vx / vy / wz：当前送入麦轮解算的目标速度
// control.host_waiting：上位机模式是否还在等待有效新命令
```

轮速目标上限仍为 4 m/s，四个电机的 PID 电流限幅仍为 ±15 A（C620 指令 ±12288）。模式切换会清除轮速 PID 历史值。
